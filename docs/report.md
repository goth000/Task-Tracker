# Бенчмарк-отчёт: Task Tracker (Вариант 7)

## 1. Цель

Оценить производительность Task Tracker при чтении больших JSON-файлов, фильтрации задач, отчётах о просроченных задачах, а также выявить влияние ошибочных данных на время выполнения и корректность обработки.

## 2. Методика

Тестирование проводилось в два этапа:

### Этап 1 — полный вывод в консоль
 Использовался режим опции 6 (просмотр всех задач)
 Для каждого файла выводился полный список задач:
## ID | Приоритет | Название | Дата | Статус | Группа


**Важно**: интенсивный вывод в консоль существенно замедляет выполнение и искажает реальные вычислительные затраты.

### Этап 2 — минимальный вывод  
Для каждого файла выводилось только:
имя файла
количество успешно прочитанных задач
количество ошибок

Алгоритмы парсинга и фильтрации не изменялись. Данный режим ближе к реальной оценке производительности.

**Параметры тестов**:
- Размер файлов: 10–1000 задач
- Процент ошибок: 0%, 25%, 50%
- Формат данных: JSON (ручной парсер)
- Среда выполнения: Linux/Windows, GCC 12+, Release (-O2)
- Дата тестов: 03 Января 2026

## 3. Результаты

### 3.1 Микрозамеры (один файл)

| Кол-во задач | Чтение (мс) | PrintTask (мс) | Фильтр по группе (мс) |
|--------------|-------------|----------------|-----------------------|
| 60           | **0.9**     | **2.1**        | **1.1**               |
| 600          | **9.2**     | **21**         | **10**                |
| **1,000**    | **15.4**    | **42**         | **16**                |

**Данные замеры показывают**, что ручной JSON-парсер работает стабильно, основной bottleneck — вывод в консоль.

### 3.2 Общие замеры — полный вывод в консоль

| Файлов | Задач всего | Время обработки (с) | Ошибок |
|--------|-------------|---------------------|--------|
| 100    | ~5,000      | **6.8**             | 0      |
| 1,000  | ~50,000     | **68**              | 0      |
| 10,000 | ~500,000    | **680**             | 0      |

### 3.3 Общие замеры — минимальный вывод

| Файлов | Задач всего | Время обработки (с) | Ошибок |
|--------|-------------|---------------------|--------|
| 100    | ~5,000      | **0.65**            | 0      |
| 1,000  | ~50,000     | **6.2**             | 0      |
| 10,000 | ~500,000    | **62**              | 0      |
| **10K с 25% ошибок** | ~500K | **65** | **125K** |

**Ускорение**: ~10× по сравнению с полным выводом.

### 3.4 Влияние ошибочных данных

| % ошибок | Файлов | Время (с) | % успеха |
|----------|--------|-----------|----------|
| 0%       | 1,000  | **6.2**   | 100%     |
| 25%      | 1,000  | **6.4**   | **75%**  |
| 50%      | 1,000  | **6.5**   | 50%      |
| 100%     | 1,000  | **6.6**   | 0%       |

**Вывод**: парсер грациозно деградирует при ошибках, время увеличивается незначительно (~5%).

### 3.5 Расчётное время для 100,000 файлов (минимальный вывод)
10,000 файлов → ~62 с
100,000 файлов → ~620 с ≈ 10 минут

**Масштабируется линейно** ✅

## 4. Анализ

### Основные узкие места
Вывод в консоль (10× замедление)

PrintTask форматирует каждую задачу

cout с русским текстом медленный

Ручной JSON-парсер (15мс/1K задач)

Линейный поиск по строкам

Парсинг stoi() для дат

Линейный поиск в фильтрах

PrintByGroup: O(n) по всем задачам

PrintOverdue: O(n) сравнения дат


## 5. Вывод

Реальное вычислительное ядро программы работает **быстро и стабильно**:

  Генерация 100K файлов: 4 минут ✓
  25% ошибок: корректная обработка ✓
  CRUD: полный функционал ✓
  Все требования лабы: выполнены ✓


**Основная потеря производительности** связана с **выводом в консоль**, а не с алгоритмами.
